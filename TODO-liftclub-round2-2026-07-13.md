# Cairntrace TODOs round 2 — remaining liftclub workaround classes (2026-07-14)

After v1.37.0's fixes were field-verified (liftclub removed its batch-click, link-click, and casing workarounds and all specs pass natively), these bug classes STILL require spec-level workarounds in liftclub. Each lists the workaround signature to grep for in liftclub's tests/e2e/flows/.

1. **Off-viewport / stuck-CSS-transition clicks into freshly-opened sheets/dialogs** — coordinate resolution lands off-viewport when the target sits inside a just-opened `UiSheet`/dialog mid-transition. Workarounds: eval DOM `.click()` in admin_calendar_class.yml (open_edit_class, cancel_class), member_booking_flow.yml + member_class_detail_cancel.yml (confirm_cancel, dialog-scoped), admin_calendar_roster.yml (click_agregar, documented-unresolved).

   **The fix sketch below is wrong — investigated 2026-07-15. There are TWO bugs here, and the box-stability idea addresses neither of liftclub's.**

   ~~Fix sketch: wait for the target's bounding box to be stable across two frames AND fully within viewport.~~

   - **1a — liftclub's actual bug is rAF throttling, not settling.** admin_calendar_class.yml's own comment records it: the sheet's enter transition *never completes in the throttled/background tab*, so the target measures at x≈1384 against a 1280px viewport and stays there — "a settle delay does NOT help since the transition never runs", and Playwright in a focused tab settles fine. The box is already stable; it is stably *wrong*. Waiting for stability would burn the budget and change nothing. Investigate `AGENT_BROWSER_ARGS=--disable-background-timer-throttling,--disable-renderer-backgrounding,--disable-backgrounding-occluded-windows` (agent-browser exposes `--args`/`AGENT_BROWSER_ARGS`) — untested against liftclub, and it did not affect the 1b repro, which is not throttling-bound.
   - **1b — a real, separate, deterministic bug: `by: selector` clicks skip the viewport guard entirely.** `runInteractiveStep` returns from the selector fast path (AgentBrowserAdapter.ts ~836-870) before reaching `detectOffViewportAfterScroll`, which only guards the ref path. A `by: selector` click into a transitioning sheet is dispatched at a coordinate the target has already left: **agent-browser exits 0 and the step reports ✓ while the app's handler never fires.** `by: role` passes the same fixture because the off-viewport poll incidentally absorbs the transition. Repro (3/3 deterministic; fixture is a 1200ms `transition: transform` sheet + a `by: selector` click, asserting the handler ran): fails on `by: selector`, passes on `by: role`.
   - **1b FIXED 2026-07-16** per the implementation note below: rect-settle guard (rAF × 2 with a 250ms frame fallback for throttled tabs) folded into the selector path's existing eval, zero extra invocations; `mockClickSequence` helper landed with it. 1a remains open.
   - **Implementation note.** A settle gate built from `get box` polling *does* fix 1b (verified: 3/3 fail → 3/3 pass) but was rejected and reverted: each read is a subprocess round-trip, so it adds ~2 invocations to every click and silently reverses the deliberate design at :839-844 ("a non-link click therefore pays no extra invocation over the scroll it already needs"). It also broke 10 tests whose ordered `execa` queues encode the exact invocation sequence. The right shape is the TODO's own words — stable across two *frames* — folded into the eval that already runs on this path (rAF × 2, compare rects in-page, one invocation), plus a `mockClickSequence` test helper first.

2. **Submit-button clicks swallowed by `@submit.prevent` forms** — specs use `press: Enter` instead. Files: admin_class_schedule.yml, admin_shop_product_crud.yml, member_profile_edit.yml, member_progress_logs.yml, member_strength_log.yml, member_wellness_log.yml.

   **Does not reproduce on v1.37 — investigated 2026-07-15. Re-test before building anything.**

   A `type=submit` button inside an `@submit.prevent` form fires its handler on a plain `click`, 5/5 runs. The buttons are real submit controls (liftclub has 43 `@submit` forms), so that part of the premise holds — but **five of the six specs blame "cairntrace v1.24"**, and v1.37.0 shipped field-verified click-delivery fixes since. The sixth (admin_class_schedule.yml) doesn't describe a submit bug at all: its comment blames "a role-based click… resolves to a stale/off-viewport coordinate (`stayed off-viewport after scrollIntoView`)" — that is item 1, not this one. A click that lands nowhere fires no submit handler, so "swallowed submit" is most likely item 1 wearing a costume. Remove one `press: Enter` workaround and run it before designing a submit probe.

   **Do not build the retry.** v1.37.0's own precedent restricts retries to controls where a double-fire is detectable and reversible (batchClickProbeScript, checkbox/radio/switch only). A submit is neither: client state is identical after 1 vs 2 submits, and the duplicate row is already committed. A wrong diagnosis costs one confusing failure; a wrong retry double-charges a member.

3. **No `select` step** — native `<select>` needs an eval workaround (admin_calendar_roster.yml). Add a first-class `select: { by, ..., value|label }` step.

   **FIXED 2026-07-16.** `select: { by, ..., value|label }` (exactly one of value | label) landed in the schema, both adapters, and the Playwright exporter. agent-browser maps to its `select` command (which matches value OR label — verified 0.31.1; a failed match exits non-zero listing options but leaves the select deselected); Playwright maps to `selectOption` strictly by the authored key.

4. **`fill`/`type` can't reach `<input type="date">`** — shadow-DOM date inputs need eval value-setting + input/change event dispatch (PAR-Q specs). Teach fill to set `.value` + dispatch events for date/time/datetime-local inputs.

   **FIXED 2026-07-16** (agent-browser `by: selector` path). The scroll eval the selector fill already pays now detects date/time/datetime-local inputs and sets the value natively (prototype value setter + bubbling input/change events) in the same eval — zero extra invocations; an invalid value fails the step with the field restored. Verified live: agent-browser's keystroke `fill` reported ✓ Done with the value left empty. Playwright's `fill()` already value-sets these natively (verified live) and stays unchanged. Semantic locators still can't reach date inputs on agent-browser — they have no presence in the a11y snapshot (only shadow spinbutton parts), so resolution fails loudly; docs say to use `by: selector`.

Hypothesis: the awaited text matched somewhere else in the DOM (hidden/stale node), or matched during a transient state.
